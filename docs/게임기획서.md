# 개요

- 게임 이름: 이세계에 전생했더니 요정과 요괴들의 최종 보스가 되었습니다

- 플레이 인원: 1명
- 개발 환경: Visual Studio 2022, C++20, glc2d
- 실행 환경: Windows PC, 키보드 조작
- 화면 크기: 960 × 600, 창 모드
- 플레이 시간: 3개 스테이지를 처음부터 클리어하는 데 약 10분
- 게임 목적: 침략자인 주인공을 조작하여 요정과 요괴의 방어선을 돌파하고 세 결계를 점령한다.
- 기획 의도: 동방풍의 화려한 탄막과 패턴 회피를 바탕으로, 플레이어가 수호자들의 입장에서 최종 보스가 되는 이야기를 만든다. 캐릭터, 세계관, 대사와 리소스는 독자적으로 구성한다.

### 스토리

주인공 레온 애쉬포드는 이세계에 전생하면서 강력한 마력을 얻는다. 그는 새로운 삶에서는 일을 하지 않고 편하게 살겠다는 생각으로, 요정과 요괴들이 살아가는 루미나리아를 자신의 영지로 삼으려 한다.

그러나 루미나리아의 주민들에게 레온은 평화로운 고향을 빼앗으러 온 침략자다. 꽃요정 릴리안 블룸, 여우 요괴 비비안 미스트우드, 결계 요괴 엘레노어 나이트베일은 각자의 영역에서 그를 막아선다.

레온은 스스로를 위대한 지배자라고 소개하지만, 수호자들은 그를 무례한 불청객으로 취급한다. 전투 전후의 짧은 대사로 레온의 허세와 수호자들의 반응을 보여준다.

세 결계를 모두 점령하면 레온은 루미나리아의 지배자가 된다. 하지만 왕좌에는 요정들이 장난을 쳐 놓고, 요괴들은 매일 항의하러 찾아온다. 레온이 꿈꾸던 편안한 생활과는 거리가 먼 모습을 보여주며 끝난다.

## 플레이 방식

### 기본 조작

| 기능 | 조작법 1 | 조작법 2 |
|---|---|---|
| 이동·메뉴 선택 | 방향키 / 숫자패드 | 기본 키 + WASD |
| 사격·메뉴 결정 | Z | Z / J, 메뉴 결정에는 Enter도 사용 |
| 다음 대사 진행 | Enter | Enter |
| 폭탄·메뉴 취소 | X | X / K |
| 저속 이동·피격 중심점 | Shift | Shift / Space / L |
| 일시정지·이전 화면 | Esc | Esc |
| 대사 빨리 넘기기 | 없음 | Ctrl / ; 누르고 있기 |
| 일시정지 중 재도전·타이틀 | 메뉴에서 선택 | R 재도전 / Q 타이틀 |

- 타이틀의 조작법에서 좌우 키로 두 방식을 전환한다. 기본값은 조작법 1이며, 선택은 게임을 켜 둔 동안 씬 이동·재도전 후에도 유지한다.
- 조작법 2는 조작법 1의 키도 함께 지원한다. Enter는 두 조작법 모두에서 대사 진행에 사용하고, 사격·폭탄으로 동작하지 않는다. 전투 중 R·Q는 동작하지 않는다.
- 사격 키 Z·J는 대사를 진행하지 않는다. 대사 진입과 매 대사 진행 뒤에는 Enter를 놓았다가 다시 눌러야 다음 대사로 넘어가며, 키를 누른 채 유지하거나 자동 반복되어도 연속으로 넘기지 않는다. 조작법 2에서 Ctrl·;를 의도적으로 누르고 있으면 0.12초마다 한 대사씩 빨리 넘긴다.
- 기본 키는 [동방휘침성 공식 조작 설명](https://www16.big.or.jp/~zun/html/th14man/html/controll.html), 추가 키는 [New Classic 개발자 공개 조작표](https://x.com/_jyunya/status/2097526902500286555)를 참고했다. 이 프로젝트는 키보드의 일반적인 QWERTY 키 값을 사용한다.

- 플레이어는 전투 영역 안에서 상하좌우로 이동하며 위쪽으로 사격한다.
- 대각선 이동 속도는 가로·세로 이동 속도와 같게 보정한다. 이동·방향 전환에는 45ms의 짧은 가속 보정을 적용하고, 키를 놓으면 즉시 멈춘다. 저속 이동으로 전환하면 곧바로 100px/s 이하로 제한한다.
- 캐릭터 그림보다 작은 원형 피격 판정을 사용하고, 저속 이동 중 중심점을 표시하여 좁은 탄막 사이를 통과할 수 있게 한다.
- 화면 밖으로 이동할 수 없으며, 화면을 벗어난 탄환과 일반 적은 제거한다.
- 전투 표시 크기는 보스 103.36×103.36px, 플레이어 64×96px, 순찰 요정·안개 사역마 40×40px, 결계 수호령 50×50px로 둔다. 플레이어 그림이 잘리지 않도록 중심 이동 범위를 x=32~448, y=48~552로 제한하고, 보스 중심 높이는 144px로 둔다.
- 탄환은 기존 이미지의 1.25배로 표시한다. 마력탄은 15×30px, 꽃잎은 20×30px, 구체는 20×20px이며 실제 속도 방향에 맞춰 중심을 기준으로 회전한다. 충돌은 기존 피격 중심점과 충돌 반경을 사용한다.

### 생명, 폭탄, 점수, 파워

- 스테이지 진입, 다음 스테이지 진행, 재도전 시 생명 3개·폭탄 3개·점수 0점·파워 0단계로 초기화한다. 생명과 폭탄은 각각 최대 5개까지 보유한다. 결과 화면에는 해당 스테이지 점수를 표시한다.
- 적탄이나 적 본체에 닿으면 생명 1개를 잃는다. 피격 후 1.5초 동안 무적이며, 깜빡임으로 상태를 표시한다.
- 무적 중에는 추가 피해를 받지 않는다. 생명이 0이 되면 실패 결과 화면으로 이동한다.
- 폭탄은 화면의 적탄을 즉시 제거하고 플레이어에게 1초간 무적을 제공한다. 적 체력에 직접 피해를 주지는 않는다.
- 폭탄 키(X, 조작법 2에서는 K도 사용)를 한 번 누를 때 폭탄 1개를 소비한다. 계속 누르고 있어도 연속 소비하지 않으며, 남은 폭탄이 0개이면 사용할 수 없다.
- 피격 무적과 폭탄 무적이 겹치면 남은 시간이 더 긴 쪽을 유지한다.
- 일반 적을 처치하면 초록색 점수 구슬과 P 파워 아이템을 각각 하나씩 떨어뜨린다. 점수는 구슬을 획득할 때 100점을 지급하고 `+100`을 잠깐 표시한다. 보스 처치 보상 5,000점은 즉시 지급한다. 화면 밖으로 퇴장한 적은 아이템과 점수를 주지 않는다.
- 탄환은 한 대상에 피해를 준 뒤 제거한다. 일반 적의 아이템 생성과 보스의 처치 보상, 각 아이템의 획득 처리는 한 번만 수행한다.
- 일반 적 처치 시 회복 아이템 5% 또는 폭탄 아이템 5% 확률로 둘 중 하나를 추가로 떨어뜨리며, 나머지 90%는 추가 아이템이 없다. 회복·폭탄 아이템은 각각 1개를 보충한다. 상한에 도달해도 획득한 아이템은 사라지며 추가 보상은 없다. 생명이 0인 플레이어는 아이템으로 부활하지 않는다.
- P 파워 아이템을 10개 모을 때마다 파워가 1단계씩 증가하며 최대 4단계·누적 40개다. HUD에 현재 단계와 다음 단계까지 모은 개수를 표시한다. 단계별로 한 번에 1·3·5·7·9발을 4도 간격으로 발사해 사격 범위가 넓어진다. 발사 간격 0.12초, 탄속 600px/s, 탄환당 피해 1은 유지한다.
- 아이템은 생성 직후 0.25초 동안 살짝 떠오른 뒤 내려오며, 12초가 지나거나 화면 아래를 벗어나면 사라진다. 점수 구슬·P 파워는 90px/s로 낙하하고 36px 이내에서 220px/s로 끌려오며, 범위를 벗어나면 다시 낙하한다. 회복·폭탄은 28px/s로 낙하하고 80px 이내에 접근하면 280px/s로 계속 끌려온다. 모든 아이템은 중심 간 거리 22px 이내에서 획득한다.

### 진행 및 승패

1. 타이틀에서 게임 시작을 선택한다.
2. 스테이지 선택 화면에서 해금된 스테이지를 선택한다.
3. 레온과 릴리안의 도입 대사 8개 후 일반 적 구간을 진행한다.
4. 일반 적 구간이 끝나면 남은 일반 적을 퇴장시키고 적탄을 정리한 뒤 보스 등장 대사 14개를 보여준다. 도입과 보스를 합쳐 총 22개 대사를 화자별 초상화·이름·본문 두 줄·현재 순서로 표시한다. 이미 떨어진 아이템은 보존하고 대사 중에는 멈췄다가 보스전에서 다시 이동한다.
5. 보스 체력을 모두 소진하면 클리어한다. 다음 스테이지가 있으면 해금하고 저장한다.
6. 1·2스테이지는 클리어 결과 화면을 표시한다. 3스테이지는 엔딩을 보여준 뒤 최종 결과 화면을 표시한다.

- 보스 체력이 절반 이하가 되면 한 번만 두 번째 패턴으로 전환한다. 전환 시 적탄을 제거하고 보스 체력은 유지한다.
- 보스 체력이 0이 되면 처치 처리를 먼저 수행하고, 두 번째 패턴을 새로 시작하지 않는다.
- 보스 처치와 플레이어의 마지막 피격이 같은 갱신에서 발생하면 클리어를 우선한다.
- 보스전 60~90초는 목표 플레이 시간이며 제한 시간이 아니다. 보스를 처치해야 클리어한다.
- 일시정지·대사·결과 화면에서는 전투 시간, 이동, 공격 주기, 무적 시간과 아이템·점수 표시 시간이 진행되지 않는다. 재개 시 멈춰 있던 시간이 한꺼번에 반영되지 않도록 한다.

### 스테이지 해금 및 저장

- 처음 실행하면 1스테이지만 선택할 수 있다.
- 1스테이지 클리어 시 2스테이지, 2스테이지 클리어 시 3스테이지를 해금한다. 열린 스테이지는 자유롭게 다시 선택할 수 있다.
- 실행 파일 폴더의 `progress.txt`에 최고 해금 스테이지 번호 1~3을 저장한다. 생명·폭탄·점수·전투 중간 상태는 저장하지 않는다.
- 저장 정보가 없거나 정수 1~3으로 읽을 수 없으면 1스테이지부터 시작한다.
- 재도전, 실패, 이전 스테이지 재클리어로 해금 상태가 낮아지지 않게 한다.
- 저장에 실패하면 이번 실행에서는 해금 상태를 유지하고, 결과 화면에 저장 실패를 안내한다.

### C++20 구현 기준

- Visual Studio 2022의 C++ 언어 표준을 `/std:c++20`으로 지정하는 것을 구현 기준으로 한다.
- 프로젝트 파일에서는 Debug/Release × Win32/x64의 네 구성에 `<LanguageStandard>stdcpp20</LanguageStandard>`를 지정한다.
- 현재 프로젝트에는 언어 표준 항목이 없으므로, 실제 구현 단계에서 설정을 반영하고 Windows에서 확인한다.

| 용도 | 사용 문법 및 자료형 | 적용 방향 |
|---|---|---|
| 객체 목록 | `std::vector` | 일반 적과 탄환 목록 관리 |
| 객체 소유권 | `std::unique_ptr` | 씬과 적·보스 객체의 수명 관리 |
| 상태 구분 | `enum class` | 게임 화면, 보스 단계, 탄환 소속 구분 |
| 시간 관리 | `std::chrono::steady_clock` | 프레임 사이 경과 시간 측정 |
| 탄막 각도 | `std::numbers::pi_v<float>` | 원형·부채꼴·회전 탄막 계산 |
| 공통 상수 | `constexpr` | 초기 생명, 폭탄, 점수 기준 정의 |

- 위 기능 중 `std::numbers`는 C++20에서 추가된 기능이다. 나머지 기능도 C++20 기준 설계 안에서 함께 활용한다.
- 이동량은 초 단위 경과 시간에 비례하게 계산한다. 현재 `GameTime::deltaTime`은 밀리초 단위이므로 초로 변환하는 기준을 통일한다.
- 기존 `Attack(GameCharacter*, int)`는 대상을 직접 지정해 피해를 주는 초기 구조다. 슈팅 전투에서는 발사 시 탄환을 생성하고, 이후 충돌할 때 피해를 주는 흐름으로 확장한다.
- 아래는 원형 탄막 계산을 설명하는 C++20 구현 예시이며, 현재 소스에 반영된 코드는 아니다.

```cpp
#include <cmath>
#include <numbers>
#include <vector>

struct BulletSpawn
{
    float x{};
    float y{};
    float velocityX{};
    float velocityY{};
};

std::vector<BulletSpawn> MakeRing(
    float x, float y, float speed, int count)
{
    std::vector<BulletSpawn> bullets;
    if (count <= 0)
        return bullets;

    constexpr float fullTurn = 2.0f * std::numbers::pi_v<float>;
    for (int i = 0; i < count; ++i)
    {
        const float angle = fullTurn * static_cast<float>(i)
                            / static_cast<float>(count);
        bullets.push_back({x, y,
                           std::cos(angle) * speed,
                           std::sin(angle) * speed});
    }
    return bullets;
}
```

## ui 구성

### 화면 배치

- 전투 화면은 왼쪽 480 × 600의 세로형 전투 영역과 오른쪽 정보 패널로 나눈다.
- 정보 영역에는 게임 이름, 스테이지 이름, 점수, 남은 생명·폭탄 아이콘, 파워와 전투 시간을 정렬한다. 기존 배경과 레온 전신 아트를 어둡게 조합하고, 자세한 조작법은 조작법·일시정지 화면에 모은다.
- 긴 게임 이름은 타이틀에서 여러 줄로 배치하고, 전투 중에는 짧게 "요정과 요괴들의 최종 보스"로 표시한다.
- 보스 체력과 현재 패턴 이름은 전투 영역 상단에 표시한다.
- 대사는 전투를 멈춘 상태에서 화면 하단 대사창과 초상화로 보여준다.
- 타이틀은 인물이 없는 밤숲 배경과 텍스트 메뉴로 구성한다. 배경은 화면보다 2.5% 크게 그려 20초 주기로 천천히 이동하며 가장자리가 비지 않게 한다. 결과 화면은 레온 전신, 스테이지 선택은 세로 목록과 선택한 수호자의 전신을 사용한다. 제목·소제목은 카페24 클래식타입 40·28px, 본문·보조정보는 모나12 텍스트 KR 22·18px를 유지한다. 원본 글꼴과 라이선스를 게임에 포함하고 프로세스 전용으로 등록한다.

### 메뉴 및 화면 전환

| 화면 | 표시 및 선택 내용 |
|---|---|
| 타이틀 | 게임 시작, 조작법, 종료 |
| 조작법 | 키 설명, 피격 중심점, 폭탄·아이템·파워 규칙 |
| 스테이지 선택 | 1~3스테이지 이름·보스·해금 여부, 잠긴 항목의 해금 조건 |
| 일시정지 | 계속하기, 재도전, 스테이지 선택, 타이틀로 |
| 클리어 결과 | 점수, 다음 스테이지, 재도전, 스테이지 선택 |
| 실패 결과 | 점수, 재도전, 스테이지 선택 |

- 잠긴 스테이지를 선택하면 전투로 이동하지 않고 해금 조건을 표시한다.
- 조작법·스테이지 선택에서 취소 키 또는 Esc를 누르면 타이틀로 돌아간다.
- 일시정지에서 취소 키·Esc 또는 계속하기를 선택하면 전투를 재개한다.
- 일시정지에서 재도전하면 현재 스테이지를 처음부터 다시 시작한다. 스테이지 선택·타이틀로 돌아가면 현재 전투를 종료한다.
- 결과·엔딩 화면에서는 현재 방식의 결정 키로 항목을 선택하거나 진행한다. 결정·폭탄은 새로 누른 순간에만 처리하여 누르고 있던 키가 반복 선택·소모로 이어지지 않게 한다.

### 동적 표현

- 전투 중 기존 숲 배경이 초당 24px씩 아래로 흘러 플레이어가 앞으로 나아가는 느낌을 준다. 높이 600px 이미지의 위쪽 96px를 겹쳐 부드럽게 연결하고, 504px·21초 주기로 반복한다. 일반 적은 정해진 경로로 이동한다.
- 배경 위치는 누적 전투 시간으로 계산한다. 도입·보스 대사와 일시정지에서는 멈추고, 재개 시 같은 위치에서 이어지며 재도전 시 처음 위치로 돌아간다.
- 캐릭터 이동과 공격, 탄환 이동, 보스 패턴 전환을 시간에 따라 표현한다.
- 피격 깜빡임, 적 처치 폭발, 폭탄 사용 효과, 보스 등장·퇴장 효과를 넣는다.
- 탄환이 밀집해도 피격 중심점과 회피할 틈을 식별할 수 있게 효과의 크기와 밝기를 조절한다.

## 주요 클래스 다이어그램

### 현재 구현 상태

- 2026.11.01 기준 타이틀·조작법·스테이지 선택·전투·일시정지·승패 결과 UI를 구현했다. `App`의 `StageResult`로 스테이지 점수·승패·전투 시간을 결과 화면에 전달한다.
- `ScenePlay`가 플레이어·탄환·일반 적·보스를 소유하고, 도입 대사 8개·90초 일반 적 구간·보스 대사 14개·릴리안 전투를 진행한다. 대사는 사격과 분리한 Enter 입력으로 한 대사씩 진행하며, 체력·충돌·무적·폭탄·점수 구슬·회복·파워·패턴 전환과 재도전 초기화를 구현했다.
- 기존 씬 구조를 확장했으며 별도 `StageManager`·`SaveData`는 아직 만들지 않았다. 아래 다이어그램은 최종 목표 설계이고, 2·3스테이지·해금 저장·엔딩은 4주차 이후 구현 대상이다.
- 1스테이지에는 순찰 요정·안개 사역마·결계 수호령을 1.5초 간격의 6회 순환으로 섞어 생성한다. 체력은 각각 3·3·5이며 릴리안 체력 500, 플레이어 탄 피해 1을 유지한다. 순찰 요정은 1.4초마다 3발(90px/s·8도 간격), 안개 사역마는 1.6초마다 1발(85px/s), 결계 수호령은 진입 후 정지한 동안 2초마다 5발(80px/s·12도 간격)의 조준탄을 발사한다. 발사 순간의 위치를 겨냥하고 발사 후에는 방향을 바꾸지 않는다.
- 안개 사역마는 하강하며 좌우 48px를 왕복하고, 결계 수호령은 2초 동안 진입·2.5초 정지 후 퇴장한다. 릴리안은 중심 (240, 144)에서 좌우 100px·상하 12px를 10.5초·7.5초 주기로 왕복하며 1단계에서 0.85초마다 7발 조준 부채탄(155px/s·8도 간격)을 발사한다. 이동 시간도 대사·일시정지에서 멈추고 재도전하면 초기화한다.
- 릴리안 2단계는 전환 후 1초를 기다리고 1초마다 36발 원형탄(125px/s)을 발사한다. 매회 6도씩 발사각을 회전하고 두 번째 링마다 5발 조준탄(175px/s)을 추가한다. 일반 적은 발사점이 플레이어보다 위에 있고 거리가 96px 이상일 때만 발사하되, 건너뛴 공격도 주기를 소비하여 뒤늦게 몰아서 쏘지 않는다. Windows 플레이에서 체감 난이도를 조정한다.
- 수집 아이템은 기존 생명·폭탄 아이콘과 단위 텍스처를 재사용한다. 별도 이미지 파일을 추가하지 않고 초록색 점수 구슬·보라색 P와 파워 표시를 그린다. 생명·폭탄은 기본 3개·최대 5개이며, 재도전 시 파워와 남은 아이템도 초기화한다.
- 기존 숲 텍스처를 재사용한 반복 스크롤을 구현했다. 전투 영역 480×600 안에서만 표시하고 이미지·자산 항목은 추가하지 않는다.

- `GameState`는 타이틀·조작법·선택·대사·전투·일시정지·결과·엔딩을, `BossPhase`는 1·2단계를, `BulletTeam`은 플레이어·적 소속을 구분하는 `enum class`로 설계한다.
- `BulletManager`는 `std::vector<GameBullet>`로 탄환을 관리한다. 플레이어 탄은 적에게, 적탄은 플레이어에게만 충돌하게 한다.
- `StageManager`는 `std::vector<std::unique_ptr<GameMob>>`와 `std::unique_ptr<GameBossMob>`로 적을 소유한다. 다른 객체의 참조는 소유권을 넘기지 않는다.
- 스테이지를 종료하거나 재시작할 때 기존 적과 탄환을 정리하고 경과 시간·점수·플레이어 상태를 초기화한다.

## 주요 시퀀스 다이어그램

### 공격과 보상

```mermaid
sequenceDiagram
    actor User as 사용자
    participant Input as GameInput
    participant Player as GamePlayer
    participant Bullets as BulletManager
    participant Enemy as GameMob / GameBossMob
    participant Stage as StageManager

    User->>Input: Z 입력
    Input->>Player: 사격 입력 전달
    Player->>Bullets: 발사 간격 확인 후 탄환 생성 요청
    loop 전투 갱신
        Bullets->>Bullets: 경과 시간에 따라 탄환 이동
        Bullets->>Bullets: 적과의 원형 충돌 검사
    end
    opt 적과 충돌
        Bullets->>Enemy: Damage(damage)
        Bullets->>Bullets: 충돌한 탄환 제거
        alt 적 체력이 0 이하
            Bullets->>Stage: 처치 알림
            alt 일반 적 처치
                Stage->>Stage: 점수 구슬·파워와 확률 아이템 생성
                Player->>Stage: 점수 구슬 획득
                Stage->>Stage: 100점 지급, 아이템 제거
            else 보스 처치
                Stage->>Stage: 5,000점 지급
            end
            Stage->>Stage: 처치 효과 요청 및 대상 제거 예약
        else 적 생존
            Enemy->>Enemy: 피격 효과 표시
        end
    end
```

- 적과 탄환은 순회 중 즉시 지우지 않고 제거 표시를 남긴 뒤 정리하여 반복자 무효화를 방지한다.
- 이미 처치 표시된 적은 추가 피해와 아이템 생성·보상 지급 대상에서 제외한다.
- 보스 처치 시 점수 지급과 별도로 스테이지 완료 처리를 한 번 수행한다.

### 구현 및 실행 확인

- 문서 확인: 기존 목차 순서, 캐릭터 이름, 게임 수치, 표·링크·Mermaid 문법이 일치하는지 확인한다.
- C++20 설정: Windows에서 네 프로젝트 구성의 C++ 언어 표준과 코드 예시·소스의 컴파일 여부를 확인한다.
- 해금: 첫 실행에서 1스테이지만 열리는지, 잠긴 항목의 진입이 차단되는지, 클리어 후 다음 스테이지가 열리는지 확인한다.
- 저장: 재실행 시 해금 유지, 저장 파일 누락·잘못된 값의 초기화, 저장 실패 안내와 실행 중 해금 유지를 확인한다.
- 재도전: 적·탄환·아이템·점수 표시·시간·점수 정리와 생명 3개·폭탄 3개·파워 0단계 복원을 확인한다. 해금 상태는 유지되어야 한다.
- 피격: 한 번에 생명 1개만 감소하고 1.5초 무적이 적용되는지, 생명 0에서 실패하는지 확인한다.
- 폭탄: X 한 번에 1개만 소비하고, 적탄 소거·1초 무적·0개일 때 사용 차단이 동작하는지 확인한다.
- 아이템: 일반 적 처치당 점수 구슬·파워가 한 번만 생성되고, 회복·폭탄 드롭 확률 분기와 획득 상한 5개가 동작하는지 확인한다. 점수는 구슬 획득 시 한 번만 오르고, 사망 후 회복으로 부활하지 않아야 한다. 점수·P의 90px/s 낙하·36px 유인·범위 이탈과 회복·폭탄의 기존 이동·유인이 구별되는지도 확인한다.
- 파워·이동: P 10개당 1단계·최대 4단계, 누적 40개 상한과 HUD 진행 개수, 1·3·5·7·9발 사격 범위, 짧은 가속 보정·즉시 정지·저속 제한, 느려진 보스 이동을 확인한다.
- 대사 입력: Z·J를 계속 누르거나 반복 입력해도 대사가 진행되지 않아야 한다. Enter 진입 전 누름·누름 유지·자동 반복을 차단하고, 떼었다 다시 누를 때만 다음 대사로 진행하는지 확인한다. 조작법 2의 의도적인 Ctrl·; 빠른 넘기기와 도입 8개·보스 14개의 화자·순서를 확인한다.
- 정지와 재개: 일시정지·대사 중 전투와 아이템·점수 표시가 멈추고, 재개할 때 탄환이나 공격 시간이 갑자기 진행되지 않는지 확인한다.
- 보스와 점수: 체력 절반에서 패턴이 한 번 전환되고, 처치 보상이 중복 지급되지 않으며, 동시 피격 시 클리어 우선 규칙이 적용되는지 확인한다.
- 최종 진행: 1→2→3스테이지, 엔딩, 최종 결과, 재도전·메뉴 복귀를 확인한다. 전체 목표 시간과 탄막 회피 가능 여부를 플레이하며 조정한다.
- 검증 환경: 현재 작업 환경은 Arch Linux다. Visual Studio 컴파일과 Windows 실행, 화면·입력·사운드 확인은 사용자가 수행한다. 이 목록은 구현 후 확인할 항목이며 실행 검증 완료를 의미하지 않는다.

## Boss Mob 클래스 구성

### 공통 구성

- 기존 `GameBossMob : public GameCharacter`를 확장하고 보스 종류별 설정으로 체력·이동·공격 주기·패턴을 구분한다.
- 주요 데이터: 보스 종류, 현재·최대 체력, 위치, 이동 목표, 현재 단계, 공격 누적 시간, 등장·전투·처치 상태.
- 주요 처리: 등장, 위치 이동, 패턴 갱신, 탄환 생성 요청, 피해 처리, 단계 전환, 처치 알림.
- `UpdatePattern(float deltaSeconds)`에서 경과 시간에 따라 공격을 요청하고, 실제 탄환 생성·이동·충돌은 `BulletManager`가 관리한다.
- 1단계는 체력 50% 초과, 2단계는 체력 50% 이하에서 사용한다. 등장·처치 연출 중에는 새 공격을 생성하지 않는다.
- 보스 종류는 `enum class BossType`으로 구분한다. 별도 보스 클래스 세 개를 만드는 대신 공통 클래스에서 설정과 패턴 함수를 선택한다.

### 보스별 패턴

| 보스 | 1단계 | 2단계 | 회피 방향 |
|---|---|---|---|
| 릴리안 블룸 | 꽃잎 부채: 플레이어 위치를 겨냥한 7발 부채탄 | 만개: 회전하는 36발 원형탄과 격회 5발 조준탄 | 작은 이동으로 조준탄을 유도하고 원형탄 사이로 회피한다. |
| 비비안 미스트우드 | 안개 추적: 발사 순간의 플레이어 위치를 겨냥한 탄 묶음 발사 | 거울 안개: 좌우 발사점에서 교차하는 탄 발사 | 조준을 유도한 뒤 이동하고 교차 지점을 피한다. |
| 엘레노어 나이트베일 | 월광 나선: 발사 각도를 조금씩 바꾸는 회전 탄막 | 최후의 결계: 한 구간을 비워 둔 고리 탄막을 반복 발사 | 회전 방향을 읽고 고리의 빈틈으로 이동한다. |

- 조준탄은 발사 후 플레이어를 계속 추적하지 않는다.
- 최후의 결계는 매번 통과할 수 있는 빈 구간을 남기고, 다음 고리까지 이동할 시간을 확보한다.
- 보스의 체력·탄속·발사 간격은 Windows 플레이 테스트로 조정하여 목표 시간과 회피 가능한 난이도를 맞춘다.
