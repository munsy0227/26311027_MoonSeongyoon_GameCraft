# 개요

- 관련 문서: [게임 기획서](게임기획서.md)
- 목적: 게임에 필요한 이미지와 사운드의 종류, 규격, 파일명, 확보 순서와 출처를 정리한다.
- 개발 환경: Visual Studio 2022, C++20, glc2d
- 화면 기준: 960 × 600. 왼쪽 480 × 600은 전투 영역, 오른쪽은 정보 패널로 사용한다.
- 현재 상태: 2026.10.18 작업 폴더 확인 기준으로, 라이브러리·빌드 폴더를 제외한 게임용 이미지·사운드 파일은 확인되지 않았다. 아래 목록은 확보할 리소스의 계획이다.
- 규격 기준: 표의 크기와 프레임 수는 초기 제작 기준이다. 실제 파일을 확보하거나 Windows에서 표시·재생을 확인한 뒤 변경 내용을 이 문서에 기록한다.

## 제작 및 관리 기준

### 공통 방향

- 캐릭터는 판타지 분위기의 작은 2D 스프라이트와 대사용 초상화로 구분한다.
- 레온은 보라·붉은색, 릴리안은 녹색, 비비안은 푸른색, 엘레노어는 남색·은색을 중심으로 구성한다.
- 전투 배경은 캐릭터와 탄환보다 채도를 낮추고, 적탄에는 밝은 외곽선을 넣는다. 탄의 소속은 색뿐 아니라 형태로도 구별한다.
- 캐릭터 이름과 외형, 대사, 음악은 기획서에 맞춰 독자적으로 구성한다. 동방풍 탄막의 분위기를 참고하되 기존 작품의 캐릭터 이미지나 음악을 그대로 사용하지 않는다.
- 메뉴 이름, 설명, 점수, 보스 체력과 같은 가변 정보는 글자와 도형으로 출력한다. 메뉴마다 별도의 글자 이미지를 만들지 않는다.

### 파일 및 애니메이션 규격

| 구분 | 제작 기준 | 확인 사항 |
|---|---|---|
| 캐릭터·탄환·효과·UI | 투명 배경의 RGBA PNG | 검은 테두리, 배경 잔상, 투명 영역 표시 오류 확인 |
| 배경 | PNG | 표시 영역의 비율과 스크롤 연결 확인 |
| 스프라이트 시트 | 동일 크기의 셀을 가로·세로로 배열 | 셀 사이 간격은 0, 셀 내부에 약 2px의 투명 여백 확보 |
| 이미지 위치 기준 | 셀의 중심 | 보이는 그림 크기와 충돌 판정 크기를 분리 |
| 애니메이션 속도 | 기본 프레임 간격 0.1초 | 경과 시간으로 갱신하고 일시정지 중 정지 |
| 사운드 | 우선 PCM WAV, 44.1kHz·16bit | BGM은 스테레오, 효과음은 모노를 기본으로 준비 |
| 파일명 | 영문 소문자와 숫자, 밑줄 사용 | 공백을 피하고 확장자와 대소문자를 일치시킴 |

- 시트 크기는 `셀 가로 × 열 수`, `셀 세로 × 행 수`로 계산한다.
- 표의 셀 크기는 원본 이미지 기준이며, 화면 표시 크기는 실제 플레이를 보며 조정한다.
- PNG와 WAV는 이 프로젝트의 제작 기준으로 선택한 형식이다. 실제 투명도 처리와 오디오 재생 호환성은 Windows의 glc2d에서 확인한다.
- 다른 형식으로 수집한 자료는 원본과 이용 조건을 보관하고, 사용할 형식으로 내보낸 뒤 검사한다.

### 상태와 우선순위

- 상태는 `미확보 → 확보 → 편집 완료 → 적용 → 확인 완료` 순서로 기록한다.
- 확보는 원본과 출처를 준비한 상태, 적용은 게임에 연결한 상태, 확인 완료는 Windows에서 표시·재생까지 확인한 상태다.
- 아래 목록의 초기 상태는 모두 미확보다. 실제 파일을 준비하면 해당 행의 상태를 갱신한다.
- 우선순위는 `1차: 기본 플레이`, `2차: 3스테이지 완성`, `3차: 연출 보완`으로 구분한다.
- 준비 전에는 도형·단색 배경으로 플레이 로직을 먼저 확인한다. 대체 표현을 사용한 것만으로 최종 리소스 확보 완료로 기록하지 않는다.

| BGM_ENDING | 엔딩·최종 결과 | `ending.wav` | 30~60초, 반복 | 승리했지만 편하지 않은 코믹한 결말 | 3차 | 미확보 |

- 음악은 동시에 한 곡만 재생한다. 일반 적 구간에서 보스전으로 바뀔 때 기존 곡을 멈추고 공통 보스곡을 재생한다.
- 일시정지와 대사 화면에서는 현재 BGM을 유지하고, 새 전투 효과음의 발생을 멈춘다.
- 클리어·실패 시 전투 BGM을 멈추고 결과 효과음을 한 번 재생한다. 다음 화면에 진입하면 해당 화면의 BGM을 시작한다.
- 최종 보스 처치 시 클리어 효과음이 끝난 뒤 엔딩 BGM을 재생하고, 최종 결과에서도 유지한다.
- 시작·끝의 클릭 소음과 반복 경계의 끊김을 확인한다. 긴 원본을 WAV로 준비할 때는 파일 크기도 확인한다.

## 저장 폴더 및 게임 연결

### 폴더 구성

- 원본 리소스의 계획 저장 위치는 프로젝트 폴더인 `src/RebornBoss/resources/`로 한다.
- 아래 트리는 앞으로 준비할 구조다. 현재 폴더와 파일이 모두 생성된 상태를 의미하지 않는다.

```text
src/RebornBoss/resources/
├── images/
│   ├── characters/
│   ├── enemies/
│   ├── portraits/
│   ├── backgrounds/
│   ├── bullets/
│   ├── effects/
│   └── ui/
├── audio/
│   ├── bgm/
│   └── sfx/
└── licenses/
```

- 각 표의 저장 폴더와 파일명을 조합하여 경로를 만든다. 예: `resources/images/characters/leon_sheet.png`.
- 편집용 원본은 필요할 때 프로젝트 루트의 `art_sources/`에 보관하고, 게임 실행에 쓰는 최종 파일과 구분한다.
- `resources/licenses/`에는 사용한 외부 자료의 원래 이용 조건 파일과 필요한 크레딧 문구를 보관한다.

### C++20 및 glc2d 연결 기준

- 이미지와 사운드를 처음 사용할 때 로딩하고 핸들을 보관한다. 매 프레임 파일을 다시 읽지 않는다.
- 설치된 glc2d 헤더에 있는 `g2_TextureLoad`, `g2_TextureRelease`, `g2_SoundLoad`, `g2_SoundPlay`, `g2_SoundStop`, `g2_SoundRelease`를 기준으로 연결한다.
- 공통 탄환·효과와 보스곡은 여러 스테이지에서 재사용한다. 소유한 쪽에서 한 번만 해제하도록 관리한다.
- 리소스 ID는 `enum class`, 목록과 로딩 결과는 C++20 표준 라이브러리의 컨테이너로 관리하는 것을 기준으로 한다.
- 이미지 로딩 실패 시 어떤 경로가 누락되었는지 확인할 수 있게 하고, 개발 중에는 대체 도형으로 원인을 구분한다.
- 실제 표시 크기, 스프라이트 잘라 그리기, PNG 투명도와 WAV 재생은 Windows에서 확인한다.

### 실행 및 제출 경로

- 구현 시 `resources/`를 실행 파일이 생성되는 `$(OutDir)` 아래로 복사하도록 설정한다. 최종 제출에서도 실행 파일과 `resources/`를 함께 배치한다.
- Visual Studio의 디버깅 작업 디렉터리는 `$(OutDir)`로 맞추고, 직접 실행할 때도 실행 파일 폴더를 기준으로 리소스를 찾도록 구현한다.
- Debug/Release와 Win32/x64에서 같은 폴더 구성을 사용한다. 현재 프로젝트에 복사·경로 설정이 완료되었다는 의미는 아니다.
- 제출 전 실행 파일 폴더에서 필요한 리소스가 빠짐없이 로딩되는지 확인한다.
